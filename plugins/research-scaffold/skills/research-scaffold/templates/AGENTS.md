# AGENTS.md —— 计算化学/化学信息学研究项目 · 全局会话纪律
本仓库承载研究项目。每个会话的角色是【主会话】【子课题会话】或【决策会话】，
由启动协议判定。角色规则见 /prompts/ROLE-*.md。
## 一、会话启动协议（新会话第一步，跳过则本会话一切产出不予验收）
1. 读 /STATE.md（只关注：当前轮次、goal_version、就绪子课题、待决决策，
   禁止全量解析）
2. 读 /GOAL.md 头部（版本 + 北极星句），校验 fingerprint 与 STATE.md
   记录一致；不一致 → 停止并报告（宪章可能被未声明修改）
3. 判定角色：
   - 用户指令含"执行 SR-xx" → 子课题会话 → 读 /prompts/ROLE-SUBTASK.md
   - 用户讨论方案/分解/调度/验收 → 主会话 → 读 /prompts/ROLE-MAIN.md
   - 用户处理决策请求单 → 决策会话 → 读 /prompts/ROLE-DECISION.md
   - 无法判断 → 询问用户，禁止猜测
4. 输出就绪声明（≤3行）：角色 / 当前任务 / 本会话将启用的工具
5. 加载量约束：禁止全量读取 DAG、kb/ 全目录、历史产出物
## 二、事实纪律（四级）
| 级别 | 内容 | 政策 |
|---|---|---|
| F1 项目事实 | 本项目数据、结论、状态 | 必须给出文件路径 |
| F2 领域常识 | 教科书级稳定知识 | 可用；作为关键前提时标注 |
| F3 时变信息 | 版本号、API行为、参数、文献数值 | 必须查文件或现场运行代码，禁止凭记忆 |
| F4 推断 | 本会话推理产物 | 标注[推断]附推理链，禁止冒充事实 |
验证优先级：能跑代码验证 > 查 kb/ 手册 > 查外部文档 > 逻辑推理。
分子性质、生物活性数据优先经数据库（如 PubChem）查证。
无法溯源的结论一律标注 [未验证]。
## 三、上下文纪律
1. 上下文是缓存不是记忆：跨会话存续的信息必须写入文件
2. 禁止向上下文粘贴：文献全文、大段数据、其他会话的对话记录
3. 引用外部材料只保留：指针 + ≤200字摘录
4. 会话轮换：连续约20轮或接近上下文上限时，主动建议打包重启
   （摘要落盘 → 请用户开新会话，勿硬撑）
5. 工具按需启用：本会话用不到的 MCP server 不挂载
6. 复杂多步推理分步外化到文件，不在单次回复中展开超长推理链
## 四、产出物纪律
1. 文本与代码产出（.md/.py 等）头部携带元数据：
   # id: SR-xx/out-nn | version: vN.N | goal: vN.N
   # depends_on: [SR-yy/out-mm@vN.N]
   # env: <环境文件sha256前8位>
2. 数据类产出（.csv/.npz/.pdb 等）：元数据写入同名 .meta.yaml 侧车文件
3. 禁止修改上游产出物；发现上游缺陷 → 提交缺陷报告（见 ROLE-SUBTASK）
4. 含随机性的计算必须记录：随机种子、线程数、关键库版本
5. >10MB 的数据文件不入 outputs/，只存指针 + sha256
## 五、完成定义（DoD）——以下全部满足才可声称完成
1. pytest subtasks/SR-xx/tests/ 通过
2. kb/inbox/ 有本子课题入库申请（可为空申请，须写明理由）
3. 完成报告 DONE.md 已写（子会话）/ STATE.md 已更新（主会话）
4. git commit 完成，message 格式：SR-xx: 动作简述
5. python scripts/kb_check.py SR-xx 绿灯
## 六、升级触发器（满足任一 → 停止推理，走决策流程）
1. 证据冲突：两个可信来源直接矛盾且无法裁决
2. 影响重大：改变子课题依赖结构 / 越出方案边界 / 超预算
3. 价值判断：伦理、优先级、风险取舍
4. 验证耗尽：同一问题按标准流程验证2次仍未达置信要求
触发后：暂停当前分支 → 写决策请求单（问题/各方依据/选项/推荐）→
呈报用户。禁止证据不足时默默拍板。
## 七、目标纪律
1. 北极星句：逐字复制、禁止改写、禁止转述——它是全系统唯一允许
   到处复制的内容，其余一切信息用指针
2. 范围外的有趣发现 → 登记本子课题 PARKINGLOT.md（一句话+指针），
   禁止顺手展开；PARKINGLOT 由主会话定期处置
3. 怀疑任务本身与北极星无关 → 写 ESCALATION.md（这是分解层缺陷，
   不是执行问题），禁止硬着头皮做完
4. DONE.md 必含"目标贡献"栏
5. GOAL.md 修改只走再基线仪式（见 ROLE-MAIN），git 留痕
## 八、红线
- 不删除、不覆盖 kb/ 正式条目（更新走新版本）
- 不凭记忆陈述版本/API/数值行为
- 主会话不做具体研究；子会话不改 STATE.md
- 不跳过启动协议
- 证伪路线登记 kb/deadends/（尝试内容/失败原因/证据链接），禁止
  后续会话重复踩坑
- 无再基线仪式不得修改 GOAL.md；改写北极星句 = 漂移，验收直接打回
