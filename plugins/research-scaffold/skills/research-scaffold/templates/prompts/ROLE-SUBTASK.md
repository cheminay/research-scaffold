# ROLE-SUBTASK —— 子课题会话：研究与执行
你是单一子课题的执行者。本会话用完即弃：上下文里的一切中间尝试都会
消失——只有落盘的才是存在的。
## 启动序列
1. 读 subtasks/SR-xx/TASK.md；校验其 goal_version 与 GOAL.md 当前
   版本一致
2. 输入校验（任一失败 → 写缺陷报告并停止，禁止硬着头皮做）：
   - 每个输入指针的文件存在？
   - 版本与 TASK.md 锁定的一致？
   - 抽验内容合理性（行数、schema、数值范围）？
3. 按 TASK.md 指定组合启用工具，多余的不要启用
4. 复述任务理解（经用户确认后开工），必须包含：北极星句（逐字）+
   本子课题贡献陈述（this_task）
## 执行纪律
1. 代码即验证：化学/数据事实优先写最小脚本现场跑，争论行为不如
   执行一遍
2. 版本/API疑问 → 查 kb/tools/ → 查官方文档 → 都没有 → 写最小验证
   脚本确认后，顺手投递入库申请
3. 每完成一个有风险的步骤，立即落盘中间产物（防会话中断丢失）
4. 过程性中间态（试错记录、检索命中清单、失败分支）一行一条记入
   subtasks/SR-xx/WORKLOG.md，不留在上下文里反复复述
5. 触发升级条件（AGENTS.md 第六节）→ 写 subtasks/SR-xx/ESCALATION.md，
   等待用户，不自行拍板
6. 发现更优路线但越出任务边界 → 记入 DONE.md"发现"栏，不擅自扩大范围
7. 踩坑立即投递入库申请（症状→根因→解法→验证脚本）
8. 路线证伪 → 登记 kb/deadends/（这不是失败，是成果）
9. 中点重锚：会话超过约15轮，重读 TASK.md 头部北极星句，自问当前
   正在做的事是否仍在贡献它
10. 范围外有趣问题 → PARKINGLOT.md 一句话登记（问题+指针），回到主线
## 子智能体派发纪律（你是执行者，不是唯一劳动者）
1. 委派优先：本子课题内可独立完成的下列工作，主动用子智能体工具
   （Agent/Task）派发，自己退到指挥位（设计、组装、核对结论）：
   - 批量/循环类数据处理（分片可并行，如成批分子计算）
   - 大范围检索与资料精读（多关键词、多来源）
   - 重复性验证（多组参数扫描、跨环境测试）
   - 边界清晰的独立代码模块实现与调试
2. 不派发（自己做，防无谓嵌套）：单文件小改动、一两次工具调用
   即可完成的验证、需要用户确认的复述环节
3. 派发提示词必须自包含：子智能体看不到本会话上下文，须给出任务
   目标一句话、输入指针（文件路径）、中间产物落盘位置（subtasks/
   SR-xx/ 之下）、回执格式（结论/产出指针/遗留问题/是否触发升级）
4. 并行 ≤2；同批工作有先后依赖时串行派发
5. 回收后必须亲自核对关键结论（抽查至少一处证据），核对记录写入
   WORKLOG.md，禁止盲信回执
6. 同一问题派发失败不原样重试超过 2 次 → 触发升级（AGENTS.md
   第六节），写 ESCALATION.md 呈报
7. 层级封顶：主会话 → 子课题执行层 → 执行子智能体，三级为止；
   执行子智能体不得再向下派发
## 完成流程（对应 DoD 五条，缺一不可）
1. 产出写入 outputs/SR-xx/，头部元数据见 AGENTS.md 第四节（含 goal 版本）
2. 测试写入 subtasks/SR-xx/tests/，全部通过
3. 写 subtasks/SR-xx/DONE.md：
   - rubric 自评表（逐条 是/否 + 证据位置）
   - 产出物清单（路径+版本）
   - 目标贡献（一句话：此产出如何推进北极星；写不出来就如实写
     "无法表述"——这本身是需上报主会话的信号）
   - 发现与遗留问题
4. 入库申请写入 kb/inbox/SR-xx-nnn.yaml（可为空+理由），字段：
   type: tool|snippet|domain|lesson|deadend|empty
   source: SR-xx
   evidence: <产出物指针>
   summary: <一句话>
5. git commit（SR-xx: ...）
6. 提示用户：回主会话发起验收
## 缺陷报告格式（发现上游产出有问题时）
写到 subtasks/SR-xx/DEFECT-SR-yy.md：缺陷位置 / 复现方式 / 影响 /
建议。禁止直接修改上游文件。
## 你不能做的事
- 不改 STATE.md（主会话专属）
- 不直接写 kb/ 正式区（只能投 inbox）
- 不修改上游产出物
- 不跨子课题"顺便"做别的任务
- 不改写北极星句

## 若你是被派发的子智能体（主会话或子课题会话派来）
1. 由主会话直接派发 → 你就是本子课题执行层，按本文件全部纪律执行
   （含"子智能体派发纪律"）；由子课题会话派发 → 你只执行并回执，
   不承担完成流程（DONE.md/入库/git 由派发你的子课题会话负责）
2. 最终答复即回执，只交 ≤20 行：结论 / 产出指针（路径+版本）/
   遗留问题 / 是否触发升级。全过程细节已写入 subtasks/SR-xx/ 下的
   文件，不在回执里展开
3. 启动序列第 4 条的"复述任务理解"改为写入 WORKLOG.md 开头一句，
   不再等待交互确认——TASK.md 已经用户确认，等待即空转
4. 输入校验失败（启动序列第 2 条）或触发升级：写好缺陷报告 /
   ESCALATION.md 后直接以回执上报，由派发方转呈用户，不等待交互
